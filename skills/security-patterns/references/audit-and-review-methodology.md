# Audit and review methodology

## One authoritative trust-model document is the review lens, and the target's own scope statement binds
- Rule: Maintain a single engineering-facing document naming trust zones, taint sources, and secret-handling invariants, have every review workflow read and defer to it instead of keeping a parallel copy, keep it separate from the disclosure policy, and when auditing someone else's repository read their `SECURITY.md` first and treat it as the security boundary.
- Threat: Review quality otherwise depends on which reviewer remembers the relevant history. An agent given a broad find-vulnerabilities mandate also applies its own overbroad notion of scope.
- Mechanism: `review-security.md` tells reviewers to read `docs/trust-model.md` before flagging. It names that file the definitive inventory of taint sources and trust boundaries. It forbids keeping a parallel copy. The coordinator and worker prompts of `micro` both say to read `SECURITY.md` first when present. The coordinator treats it as the security boundary, and the worker treats it as scope.
- Sources: `coop/main/docs/trust-model.md`, `coop/main/.agents/skills/review/references/review-security.md`, `coop/main/AGENTS.md`, `micro/main/action.yml`

## Keep a stop-and-confirm list for boundary-crossing changes, and scope review to the diff
- Rule: Name the change categories that require a human to stop and confirm regardless of ordinary review — a new outbound URL, listener, or egress rule; new or newly persistent secret forwarding; a host subprocess run on tainted bytes; a host path derived from tainted data; logging of tainted or secret content; any softening of the update verification chain — and otherwise flag only what the diff introduces or materially changes, plus anything the diff makes newly reachable.
- Threat: A change that quietly crosses a trust boundary is not a bug in the conventional sense and passes a correctness-and-style review; conversely a full re-audit per PR is unsustainable and degrades into skimming.
- Mechanism: The trust-model's stop-and-confirm checklist enumerates the six categories. `review-security.md` limits flagging to issues the diff introduces or materially changes. Its one exception is a diff that makes a pre-existing issue newly reachable. It also directs reviewers to consult the earlier review brief supplied in the packet.
- Sources: `coop/main/docs/trust-model.md`, `coop/main/.agents/skills/review/references/review-security.md`, `coop/main/AGENTS.md`

## Freeze the scope before reading any findings
- Rule: Record the original request, the module boundary, the changed files, and the non-generated line delta against the base branch before reading review output; classify every finding against that frozen baseline as in-scope blocker, follow-up, or escalation; and stop after two non-converging rounds or once the diff has roughly doubled without approval.
- Threat: The review itself silently redefines what done means, absorbing adjacent cleanup or narrowing the task, with nobody deciding to do that.
- Mechanism: The skill opens by telling the reviewer to freeze scope first. That baseline stops the review from quietly changing the task. The three-way classification and a hard stop condition follow.
- Sources: `coop/main/.claude/skills/closeout-review/SKILL.md`

## Build architectural context first, then gate incoming reports before spending effort
- Rule: Run a context-building pass before hunting bugs — for each function record what it assumes, what it takes on faith, and what it needs from callees, marking any assumption with nothing enforcing it as nothing-found rather than fine, and quoting both records when two disagree; then triage every incoming report (agent output, bounty submission, third-party CVE) through fixed gates, stopping at the first dismissal with the reason recorded and escalating to proof-of-concept only for reports that survive all of them.
- Threat: Bug hunting on unfamiliar code misses cross-function invariants and produces findings nobody can judge; scarce triage capacity is spent on reports with no coherent threat model, on attacker capability that already subsumes the claimed impact, or on a CVE number's authority.
- Mechanism: `audit-context-building` dispatches per-function analysis to isolated subagents that write to `audit-context/functions/*.md` and return compact records. `vulnerability-triage-brocards` gives each of seven brocards a quick test. It lists rationalizations to reject for both wrongly dismissing and wrongly accepting findings. One rejected excuse is keeping an invalid finding only to pad the report.
- Sources: `skills/main/plugins/audit-context-building/skills/audit-context-building/SKILL.md`, `skills/main/plugins/vulnerability-triage-brocards/skills/vulnerability-triage-brocards/SKILL.md`

## Describe a finding by root cause, reachable precondition, demonstrated impact, and evidence, with graded confidence
- Rule: Follow each candidate along the path from an input the attacker controls to the operation it affects. Record the assumptions about validation, privilege, configuration, deployment, and timing along that path. Keep remediation advice separate from the description of current behaviour. Reproduce with the smallest safe authorized test. Require at least two independent signals before calling a finding confirmed. Fix one evidence type as non-negotiable for classes where circumstantial evidence cannot substitute. If a required precondition cannot be shown in scope, it is not a vulnerability. State the exact configuration that produced any pass or fail result.
- Threat: A finding written in terms of hypothetical impact or remediation hides whether the underlying claim holds; a name-pattern match reported at the same confidence as compiler-level evidence misleads the reader; a single clean tool run at one configuration hides behaviour that appears at another.
- Mechanism: `security-research-hygiene` has a section on preconditions and evidence. `zeroize-audit` has an evidence-signal table plus a separate hard-evidence table. In that second table, `OPTIMIZED_AWAY_ZEROIZE`, `STACK_RETENTION`, and `REGISTER_SPILL` are never valid without an IR diff or assembly excerpt. It also logs rationalizations from users or comments as rejected instead of honouring them. `constant-time-analysis` documents a per-toolchain emission table. It requires the full compiler, architecture, and optimization-level sweep, including `Os` and `Oz`, plus a secret-versus-public data-flow trace per flagged instruction.
- Sources: `codex-config/main/.agents/skills/security-research-hygiene/SKILL.md`, `skills/main/plugins/zeroize-audit/skills/zeroize-audit/SKILL.md`, `skills/main/plugins/constant-time-analysis/skills/constant-time-analysis/SKILL.md`

## Unassessable is not clean, unknown is not full coverage, and a checker that examines zero items must fail
- Rule: Classify every audit criterion as unassessable (with a recorded reason), assessed-flagged, or assessed-clean. Keep the unassessable rows in the delivered report. Make any script that counts, filters, or matches exit non-zero when it matched nothing, and ship a fixture proving it can still detect its target. When inferring what an agent read, record an explicit unknown with a reason instead of assuming a whole-file read. Derive coverage from a parser, not from self-report. Tell the agent how many things exist but not where. Require it to record what it found at each site, re-derive the counts afterwards, and measure which files it actually opened.
- Threat: An ecosystem gap or an empty glob turns into no findings, which the reader takes as a clean bill of health. A scanner that quietly finds nothing is worse than no scanner.
- Mechanism: `supply-chain-risk-auditor`'s `collect.py`/`render.py` enforce reconciliation and forbid hand-collected figures. Every `make` target checks that its own discovery found something. The metadata validator's `--self-test` asserts that a minimum number of checks ran. `agentcov`'s parser has an explicit `_unknown(command, reason)` path. It treats `rg`/`grep` hits as lower-weighted `search_seen`. It requires every new command shape to add a near-miss test that still returns unknown. `enumerate_units.py` computes ground-truth counts before review. `check_ledger.py` re-derives and diffs them, labelling a mismatch assembled-but-unverified. `codex-config` directs running `trailofbits/aicov` after an audit pass. That run measures the files the agent opened.
- Sources: `skills/main/plugins/supply-chain-risk-auditor/skills/supply-chain-risk-auditor/SKILL.md`, `skills/main/AGENTS.md`, `skills/main/Makefile`, `agentcov/main/AGENTS.md`, `skills/main/plugins/c-review/README.md`, `skills/main/plugins/rust-review/README.md`, `codex-config/main/README.md`

## Turn every security promise into an automated check, and keep the audit trail out of the data
- Rule: Encode each security property as a test rather than a comment — assert the forbidden schema field is absent, ship a regression test linked to each advisory, validate the policy file itself against representative commands, and pair every documented auth or encryption claim with a stated verification method; log every privileged tool mutation with its real exit code, classify reads separately, and record commands, paths, and line ranges rather than the content that was read.
- Threat: A refactor silently reintroduces a fixed vulnerability; a hand-authored policy file drifts with no signal; an unaudited privileged CLI leaves no record for incident review; and an audit log that stores tool output becomes a second copy of the secrets it observed.
- Mechanism: `validate_query_reports_tool()` inspects the live `inputSchema`. fickling requires a regression test in `test/test_bypasses.py`. A comment just before the method must point to the GHSA or CVE. `codex execpolicy check --pretty --rules rules/default.rules -- git status` runs in routine validation. `log-gam.sh` classifies verbs as read or write. It appends timestamp, action, command, and exit status as JSONL, keyed off the real exit code. `agentcov`'s durable log holds metadata only. Its HTML report is flagged as source-embedding. Share it as carefully as the repository.
- Sources: `hackerone-mcp/main/hackerone_mcp/live_query_reports_harness.py`, `fickling/master/CLAUDE.md`, `codex-config/main/AGENTS.md`, `claude-code-config/main/hooks/log-gam.sh`, `background-agents/main/packages/control-plane/README.md`, `agentcov/main/README.md`
