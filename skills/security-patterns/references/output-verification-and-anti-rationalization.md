# Output verification and anti-rationalization

## Audit every claim against a tool result, and never end a turn on a promise
- Rule: Before reporting progress, back every claim with output from a tool run in this session. Report only what you can cite, state plainly what is unverified, show failing test output, and name skipped steps. If your final paragraph announces a plan or a next step, do that work now instead of ending the turn.
- Threat: Self-belief substitutes for evidence, masking skipped verification and unapplied fixes behind a completed-looking report.
- Mechanism: Prose rules in the always-loaded CLAUDE.md layer tell the agent to report only work backed by evidence. They say to state explicitly when something is not yet verified, and never to end a turn with a promise.
- Sources: `claude-code-config/main/claude-md-template.md`

## Gate the declaration of doneness, not only the actions
- Rule: Put a structural check between the agent and its own completion claim. Have an independent fast model inspect the final response for rationalization language. Examples include calling a problem pre-existing, out of scope, or something to leave for follow-up. Reject the stop with a corrective instruction. For multi-phase verification work, scan the transcript for evidence that every required phase actually ran before allowing termination. Do not add vague text telling the model to double-check its answer. Encode the check as a hook, script, or validator that cannot be talked out of firing.
- Threat: An agent under context pressure reports success on unfinished work, or declares a verdict without having run the phases the verdict depends on; generic self-verification scaffolding in a prompt measurably worsens output instead of catching this.
- Mechanism: A `Stop` hook of `type: "prompt"` sends the response to a fast model instructed to return raw JSON only (`{"ok": false, "reason": "..."}`), whose reason becomes the next instruction; `fp-check`'s `Stop` and `SubagentStop` hooks check six named phases plus a six-gate review and a per-bug verdict with evidence; `skills/main/AGENTS.md` states the prompt-scaffolding inversion explicitly.
- Sources: `claude-code-config/main/README.md`, `skills/main/plugins/fp-check/hooks/hooks.json`, `skills/main/AGENTS.md`

## Validate a consequential finding with an agent that did not produce it
- Rule: Route every candidate finding or divergence to a different model or a fresh agent for refutation, drop anything the refuter knocks down, require an absent verdict to record the search patterns tried and their results, and do not mistake an approval-routing reviewer setting for finding validation.
- Threat: The agent that produced a finding is biased toward confirming it and is poorly placed to catch its own missing precondition or misread code path; a search that stopped early looks identical to a genuine absence.
- Mechanism: `codex-config` says to give each candidate a second pass by someone other than the finder. That reviewer is another model or a new agent, and it re-checks the finding against a short plan note. It adds separately that the `approvals_reviewer = auto_review` setting governs command approvals only. Finding validation therefore needs its own review pass. `spec-to-code-compliance` dispatches one refuter re-reading the code and one re-reading the specification every run. `insecure-defaults` splits collect-only discovery from a refuting verify phase. In discovery, the sweeps gather evidence without passing judgment.
- Sources: `codex-config/main/README.md`, `skills/main/plugins/spec-to-code-compliance/skills/spec-to-code-compliance/SKILL.md`, `skills/main/plugins/insecure-defaults/README.md`

## Frame the task so that the easy out is closed
- Rule: Instruct the agent not to manufacture findings. Require a plausible path to confirmed impact with a real proof of concept. Define an explicit negative-result output so an empty result is a first-class answer. Write autonomous goals as termination contracts. Each contract has a measurable end state, the exact command that proves completion, invariants the solution must not violate, and a stop bound. Ask reviewers for every finding with a severity attached. Filter to the bar in a later pass rather than instructing suppression during discovery.
- Threat: A bare instruction to find vulnerabilities rewards padded or speculative output. A maintainer experiences that output as a drain on their time, comparable to a denial of service. An underspecified goal rewards deleting code or narrowing tests to satisfy the letter of the completion gate. Telling a reviewer to report only high-severity issues collapses recall while precision appears to rise.
- Mechanism: `micro`'s coordinator prompt forbids manufacturing findings. It defines a good scope as a plausible route to confirmed security impact, not a bug decided in advance. Its worker prompt requires the exact negative output `WORKER-{{SPEC}}-NO-FINDINGS`. `goal-prompt`'s deterministic formatter enforces the contract shape and warns on a missing stop clause rather than accepting an open-ended goal. `skills/main/AGENTS.md` names severity pre-filtering as a prompt problem that looks like a capability problem, fixed downstream via `severity_filter`.
- Sources: `micro/main/action.yml`, `skills/main/plugins/goal-prompt/README.md`, `skills/main/AGENTS.md`, `codex-config/main/README.md`

## A report may not exceed, contradict, or silently complete its own data
- Rule: Validate at render time that every rendered finding points to a line genuinely present in the captured diff and that every flag in the machine-readable artifact appears in the rendered tables; exclude or explicitly report output from scans that failed, skipped, covered nothing, or ran partially; require a check to print a marker proving it executed rather than inferring reachability from an exit code; and resolve gate severity through the rule definition, never from an optional result field alone.
- Threat: A partial scan presented as complete is more misleading than running no scan. An exit code cannot distinguish an import error from a genuinely triggered assertion. Reading `result.level` directly scores a CodeQL run as clean regardless of how many errors it found.
- Mechanism: `render.py`'s `check_no_forged_lines` and `check_flags_reconcile`; `merge_sarif.py --scans scans.json` drops findings from failed scans and prints the exclusions; `post-patch-validation` requires a flushed `PPV_REACHED` line on stdout (deliberately not scanning stderr, where a traceback echoing source could satisfy the check); the SARIF skill's documented fallback order ends at the matched rule's `defaultConfiguration.level`, joined by `ruleIndex` or `ruleId`.
- Sources: `skills/main/plugins/supply-chain-risk-auditor/skills/supply-chain-risk-auditor/scripts/render.py`, `skills/main/plugins/review-walkthrough/README.md`, `skills/main/plugins/static-analysis/skills/semgrep/SKILL.md`, `skills/main/plugins/post-patch-validation/skills/post-patch-validation/SKILL.md`, `skills/main/plugins/static-analysis/skills/sarif-parsing/SKILL.md`
