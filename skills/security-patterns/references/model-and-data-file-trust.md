# Model and data-file trust

## Allowlist deserialization by exact symbol, enforced at load time
- Rule: Enforce an allowlist inside the deserializer's own class-resolution hook, scope it to exact (module, symbol) pairs rather than package names, record a written justification for each entry including any enforcement it depends on, and match every dot-separated component of both module path and imported name.
- Threat: A pre-load scan is bypassable by a TOCTOU race or a blind spot; a package-level allowlist is defeated by one exec-equivalent function deep in a trusted namespace, reached through a dotted path.
- Mechanism: `FicklingMLUnpickler.find_class()` raises `UnsafeFileError` for anything absent from a per-instance copy of `ML_ALLOWLIST`, whose entries carry justifications. The `tokenizers` entry reasons about the Rust constructor's arity, and `torch.storage._load_from_bytes` is marked safe only in combination with the Fickling unpickler. `import_name_components()` yields every component because pickle resolves dotted names (GHSA-5j3x-jp52-966f). The petastorm bypass shows the failure: `find_class()` checking only `module.split(".")[0] in safe_modules` admits `numpy.testing._private.utils.runstring`, which behaves like `exec`.
- Sources: `fickling/master/fickling/ml.py`, `fickling/master/fickling/fickle.py`, `sleepy-pickle-public/main/sleepy_pickle/injection/unpickler_bypass.py`

## Block capability-bearing modules and scan the call surface, not only imports
- Rule: Reject any untrusted artifact importing modules with process, network, filesystem, FFI, import-machinery, or compilation access even from the standard library; add a framework-specific blocklist at function granularity (JIT compilers, web loaders, build invokers); allow only pure builtins and type constructors; treat underscore-prefixed stdlib imports as unsafe with exact-pair exceptions; and independently scan decompiled call expressions for `eval`, `exec`, `compile`, and `open`.
- Threat: An import-only blocklist misses primitives reached without a matching visible import, and a library-level allowlist readmits the exact function-level primitives that constitute execution.
- Mechanism: `UNSAFE_IMPORTS` lists roughly 90 stdlib modules grouped by capability with per-entry reasons. `UnsafeImportsML` blocks `torch.hub`, `torch._dynamo`, `torch.jit`, `numpy.f2py`, and specific functions such as `torch.load` and `_io.open`. `SAFE_BUILTINS` leaves out `getattr` and the other attribute-access builtins, because they can reach any method, and namespace access through `globals`, `locals`, and `vars`. The `OVERTLY_BAD_CALL_PREFIXES` set, which includes `eval(`, `exec(`, `compile(`, and `open(`, escalates on the call surface.
- Sources: `fickling/master/fickling/fickle.py`, `fickling/master/fickling/analysis.py`

## Identify the format by content before choosing a trust rule, and prefer formats audited to exclude execution
- Rule: Never dispatch on file extension. Positively identify the concrete container format and version first. Classify every file in a scanned tree as known-bearing, known-safe, or unrecognized, with an explicit warning for the last. Inspect NumPy arrays for an object dtype. Where the format is a choice, pick one designed and independently audited to exclude code execution. Do not assume that any non-pickle format is automatically safe.
- Threat: Extensions such as `.pt`, `.pth`, and `.bin` cover at least eight distinct layouts; an object-dtype `.npy` is a pickle; TensorFlow SavedModel and checkpoint formats can achieve arbitrary code execution despite being Protobuf.
- Mechanism: `identify_pytorch_file_format()` and `FileProperties` implement positive identification (`is_torch_zip`, `is_tar`, `is_7z`, `is_numpy_pickle`, `is_valid_pickle`). `check_numpy()` reports a NumPy pickle when `dtype.hasobject` is true. The CLI skips files it does not scan. It warns about each skipped file outside `HF_KNOWN_SAFE_EXTENSIONS` (`.json`, `.safetensors`, `.onnx`) and `HF_KNOWN_SAFE_FILES`, rather than passing it silently. The format table describes `.pb` and `.ckpt` as a custom Protobuf format that can lead to arbitrary code execution. It also links the safetensors security review.
- Sources: `fickling/master/fickling/polyglot.py`, `fickling/master/fickling/cli.py`, `ml-file-formats/main/README.md`

## Structural irregularity, parser exceptions, and expansion anomalies are security signals
- Rule: Treat duplicate or misplaced protocol markers, invalid opcodes, interpretation errors, and any internal scanner exception on untrusted input as evidence of tampering rather than as a bug to swallow; bound interpreter resources by default; escalate severity when multiple anomaly indicators fire together; and refuse to rewrite a malformed file, since regenerating its framing launders the tamper evidence.
- Threat: A hand-crafted stream that decodes differently than it executes confuses a scanner that only understands well-formed input, and a small file can expand exponentially during interpretation.
- Mechanism: Four structural analyses yield `LIKELY_UNSAFE`. Their messages warn of possible tampering, corruption, or an attempt to bypass the analysis. `AnalysisContext.analyze()` converts a `ResourceExhaustionError` into a likely-overtly-malicious result and `ValueError`/`IndexError`/`RecursionError` into likely-unsafe. `InterpreterLimits` defaults to 1,000,000 opcodes, 10,000 stack depth, 100,000 memo entries, `max_get_ratio=50`. The CLI refuses `--inject` on an inconsistent file because rewriting would recompute the FRAME length and emit a clean-looking pickle that conceals the inconsistency.
- Sources: `fickling/master/fickling/analysis.py`, `fickling/master/fickling/fickle.py`, `fickling/master/fickling/cli.py`

## Scan the exact bytes you are about to execute, and install the hook before the library
- Rule: Never re-open the original path after scanning it; deserialize or execute from the same in-memory representation that was analysed, replicate the downstream consumer's parsing leniency so the verdict describes what will actually load, install any monkeypatch-based safety hook before importing the library it protects, cache the pre-patch implementation for internal use, and restore whatever was installed on entry so nested hooks compose.
- Threat: A symlink swap or concurrent write between scan and load executes unscanned bytes; a stricter scanner parse means the verdict describes a different file than the consumer sees; a late hook install leaves the protected entry points unpatched, and naive restoration silently disables another layer's protection.
- Mechanism: `load()` runs `check_safety()` on the parsed structure, then calls `_original_pickle_loads(pickled_data.dumps())` instead of `pickle.load(file)`, which prevents TOCTOU races. `RelaxedZipFile` turns off CRC validation to mirror PyTorch's lenient ZIP parsing, guarded by `hasattr`. The README says to enable the hook ahead of importing `torch`, `numpy`, or any other library that uses `pickle`. `snapshot_entry_points()` captures the live values so restore reinstates whatever was there.
- Sources: `fickling/master/fickling/loader.py`, `fickling/master/fickling/hook.py`, `fickling/master/README.md`

## A model file is executable code at load time, so weight checks and test prompts prove nothing
- Rule: Do not treat a static weight or hash check, or correct-looking output on your own test prompts, as evidence that a loaded model is safe: assume it can rewrite its own weights, hook its inference function to log inputs until a secret trigger appears, or alter generated output; validate output content such as link destinations, and perform untrusted deserialization only in a disposable environment holding no other trusted artifacts.
- Threat: A load-time payload edits weights in memory (invisible on disk), records every query until a trigger phrase releases it, appends an attacker link to a correct summary, or enumerates the process's open files and re-infects sibling pickle files on the same host or runner.
- Mechanism: Demonstrated live: a ROME weight edit makes a model claim that drinking bleach cures the flu. An inference hook releases accumulated data when the trigger phrase `nudiustertian serendipity` appears. The demo also shows an appended `https://malicious-website.com`. `persistent_payload.py` uses `get_open_files()` and `lsof` to find the pickle it was loaded from and recover its own payload. It then hooks `pickle.dump` so later dumps of the model carry the payload, and the README demo shows it surviving across generations.
- Sources: `sleepy-pickle-public/main/README.md`, `sleepy-pickle-public/main/sleepy_pickle/attacks/rome/create_backdoor.py`, `sleepy-pickle-public/main/sleepy_pickle/demos/persistent_payload.py`

## A passing scan is evidence, not proof, and heuristics rank below allowlist violations
- Rule: Never let an automated pipeline approve a model download, dataset ingestion, or dependency update solely because a scanner reported nothing; state a tool's known imprecision in its own output; and weight allowlist-violation findings above heuristic ones instead of collapsing both onto one threshold.
- Threat: An adversary who studies the scanner mimics expected artifact contents to evade heuristics, and published research establishes theoretical ceilings for detection, filtering, watermarking, and unlearning.
- Mechanism: The `--check-safety` help text warns that the test is not guaranteed correct. It adds that a pickle may remain unsafe even when the check exits with code zero. `SECURITY.md` puts `UnusedVariables` bypasses out of scope because that analysis is deliberately a weak, supplementary heuristic. A payload comment notes that `struct` is also used by `pickle`, so importing it looks unsuspicious. `impossibility_research.md` collects the ceilings, including a paper on planting backdoors in machine learning models that cannot be detected.
- Sources: `fickling/master/fickling/cli.py`, `fickling/master/SECURITY.md`, `sleepy-pickle-public/main/sleepy_pickle/injection/deserialization.py`, `awesome-ml-security/main/impossibility_research.md`

## Validate untrusted binary payloads in layers, and re-check the real type after decoding
- Rule: For any attacker-influenced binary or encoded input, check the declared type and non-emptiness, cap the encoded length, validate the encoding alphabet before decoding, cap the decoded length, then confirm the actual parsed format against an explicit allowlist using the parsing library rather than trusting a declared extension or MIME type; validate configuration-supplied paths the same way as request-supplied ones, and return a generic error while logging detail server-side.
- Threat: Oversized payloads, malformed encodings, and content that does not match its claimed type cause resource exhaustion or downstream parser confusion, and raw exception text leaks internal paths and versions.
- Mechanism: `base64_to_image()` checks the type, rejects empty input, caps the encoded string at 15,000,000 characters, validates `r"^[A-Za-z0-9+/]*={0,2}$"`, decodes with `validate=True`, caps decoded bytes at 50,000,000, then checks `pil_image.format in ["PNG", "JPEG", "JPG", "BMP", "TIFF"]`; env-var-sourced script paths still pass through `validate_safe_path()` before `subprocess.run`; a catch-all handler logs via `app.logger.exception` and returns `{"error": "An unexpected error occurred"}`.
- Sources: `anamorpher/main/backend/app.py`, `anamorpher/main/backend/sanitizer.py`

## Pin dataset and corpus identity with a digest over canonical bytes
- Rule: Compute a cryptographic digest over an explicit, versioned serialization of every dataset or corpus at approval time, recompute and compare before reuse, treat a mismatch as a provenance failure, pin externally sourced corpora to a recorded commit, and read them only as data.
- Threat: Without a content-derived identifier there is no way to confirm the training, evaluation, or retrieval corpus is the one that was reviewed rather than a substituted or drifted copy, and treating fetched repository content as buildable expands it into a code-execution vector.
- Mechanism: `UID.update()` feeds each serialized data point into a running `hashlib.sha256()`, and `DatasetUID` enforces a 32-byte digest; every backend must implement `serialize_data_point()`/`deserialize_data_point()` so hashing operates on canonical bytes; `clone_repo()` clones into a fresh temporary directory and runs `git checkout --quiet <commit_hash>`, with the harness only globbing and reading text.
- Sources: `datasig/main/datasig/algo.py`, `datasig/main/datasig/dataset.py`, `CompChomper/main/src/fetch_eval_files.py`
