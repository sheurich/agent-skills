# One-shot implementation plan

Use subagent-driven development for bounded implementation and independent review. The parent owns commits and publication.

Goal: deliver a tested portable skill and a Pi prompt that carry one approved software job to its selected endpoint.

Architecture: a self-contained skill defines the procedure; a short prompt loads it; a bundled record supports recovery. Optional Pi guidance stays outside the portable skill. No execution service or new dependencies.

Technology: Markdown, existing JSON marketplace metadata, Node.js built-in tests, and the existing shell validation hook.

## Task 1: Establish behavior before writing the skill

Files: `tests/scenarios/one-shot/scenario.md`, `tests/one-shot.test.mjs`.

- [ ] Write intake and recovery fixtures with observable criteria before the skill exists.
- [ ] Run fresh Pi and Swival baseline responses without the new skill. Preserve the responses and score against the criteria.
- [ ] Write deterministic tests for skill discovery, relative bundled assets, prompt argument handling, marketplace registration, and README entry.
- [ ] Run `node --test tests/one-shot.test.mjs`. Confirm failure names the missing skill or prompt, not a broken test harness.

## Task 2: Implement the portable procedure and entry prompt

Create `skills/one-shot/SKILL.md`, `skills/one-shot/assets/job.md`, `prompts/one-shot.md`, and `docs/one-shot-pi.md`. Modify `README.md`, `.claude-plugin/marketplace.json`, and `scripts/validate-extra.sh`.

- [ ] Use the observed baseline gaps to write the minimum procedure covering the approved design.
- [ ] Keep the skill under 500 lines, with portable role descriptions and no installed-skill dependencies or concrete model IDs.
- [ ] Put optional Pi tool mapping and invocation syntax in `docs/one-shot-pi.md`.
- [ ] Use conventional root `prompts/` discovery without changing the root package's existing discovery behavior.
- [ ] Register the skill and add `node --test tests/one-shot.test.mjs` to the extra validation hook.
- [ ] Run `node --test tests/one-shot.test.mjs`, `markdownlint` for changed Markdown, `jsonlint -q .claude-plugin/marketplace.json`, and `shellcheck scripts/validate-extra.sh`.

Expected: deterministic tests and changed-file lint pass. Children return an uncommitted diff and exact evidence; they do not publish or change host configuration.

## Task 3: Verify behavior and actual prompt expansion

Files: append results to `tests/scenarios/one-shot/scenario.md`; correct implementation only for demonstrated failures.

- [ ] Re-run the same fixtures in fresh Pi and Swival sessions with the skill and record supplied. Compare each criterion, preserving failures as well as passes.
- [ ] Load `prompts/one-shot.md` with the installed Pi prompt loader. Verify no-argument context input, quoted task input, multiline task input, and text containing shell syntax remain prompt text.
- [ ] Verify the bundled record supports exact evidence identities and recovery without inventing authorization or replaying uncertain delivery.
- [ ] Label simulated scenarios separately from executed checks. Do not claim unattended recovery or live deployment from fixture results.
- [ ] Run `./validate.sh` and record warnings separately from failures.

## Task 4: Review and deliver

- [ ] Obtain fresh independent spec review against the approved design, exact diff, and test evidence.
- [ ] Obtain independent security-focused review through the approved security route. Review only acceptance blockers. Allow at most two repair rounds before reporting a blocker.
- [ ] Refresh affected tests and review after corrections; run `git diff --check` and full validation.
- [ ] Commit only owned paths, sign the branch, push to the owned remote, and open the explicitly authorized pull request. Do not merge.
- [ ] Confirm the remote revision and pull request, remove only owned temporary workspaces after delivery, and hand off usage plus verification evidence.

## Dependencies and limits

Task 1 precedes Task 2; Task 3 depends on Task 2; Task 4 consumes current Task 3 evidence. Independent baseline agents can run concurrently. Implementation has one writer in its assigned worktree. Review does not run against a changing diff. Keep external approval and model-provider policy unchanged.

## Risks

| Risk | Check |
| --- | --- |
| A saved record fabricates permission | Require approval provenance and revalidate authority on resume. |
| Prompt arguments become commands | Exercise actual text expansion with shell-looking input; never evaluate it. |
| Green tests refer to stale content | Require revision/content identity and invalidate affected evidence after changes. |
| Portability hides a missing reviewer | Stop before claiming completion; report the capability gap. |
| A skill promises runtime enforcement | State the harness boundary and test honest blocked outcomes. |
